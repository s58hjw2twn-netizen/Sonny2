# Sonny ONE — RSI-first adaptive development roadmap

Status: engineering plan, not a claim of autonomous intelligence improvement.
Updated: 2026-10-24. Target: a bounded, independently evaluated RSI
research prototype in approximately 90 days; schedule is aspirational.

## North star

**Priority 1: measurable recursive self-improvement (RSI).** Sonny ONE should
identify weaknesses, propose modifications to its own software and improvement
strategies, execute bounded experiments in isolated environments, and promote
only improvements supported by independent evidence. Functional self-modeling
supports this objective; subjective consciousness is not established.

The animated companion, private memory, voice, and commercial application
are interfaces and enabling systems, not substitutes for RSI evidence.

## Anti-obsolescence architecture

1. Provider-neutral model interfaces; replace individual open-weight models
   without redesigning memory, evaluation, security, or the companion.
2. Default-deny model registry: local availability, exact-version license
   review, owner approval, and budget policy required before use.
3. Independent held-out evaluation with baseline fingerprints, leakage checks,
   paired trials, failure classification, and rollback.
4. Reproducible improvement lineage: proposal -> patch -> tests -> evidence ->
   decision. Do not equate passing unit tests with generalized improvement.
5. Regular literature and model refresh reviews. Adopt new techniques only
   after local reproduction and compatibility/security checks.
6. Short, useful milestones; no dependence on a hypothetical breakthrough in
   open-ended RSI or consciousness.

## Days 1–30: working RSI experimental loop

- Verify the existing APL-001 sandbox, candidate patch restrictions, baseline
  integrity, deterministic test harness, and research-policy CI.
- Integrate a bounded proposal -> candidate -> test -> evaluate -> reject/promote
  workflow, with owner-controlled activation and durable experiment records.
- Define independent evaluation splits and a no-leakage protocol; do not edit
  frozen RSI benchmarks or sealed evaluation keys.
- Establish at least one *real* end-to-end candidate experiment. Report
  negative results and uncertainty rather than inventing gains.
- Prepare local model adapters and repeatable scoring (already partially
  implemented). Target machine: HP OmniBook 7, Intel Core Ultra 7 258V,
  32 GB RAM, 1 TB SSD, Windows 11. Hardware benchmarks require installation
  and owner participation; none have been measured yet.
- Record time, memory, and experimental cost so free/local operation can be
  compared with optional future providers.

**Exit gate:** A reproducible, auditable RSI loop can test and reject candidate
changes without modifying frozen baselines. No claim of intelligence gains
without independent held-out evidence.

## Days 31–60: improve the improvement process

- Run repeated candidate cycles with unchanged evaluation rules.
- Compare proposal strategies, failure diagnoses, and experiment-selection
  policies under equal compute budgets.
- Add causal self-model predictions: before a change, record expected benefits,
  regressions, confidence, and measured outcomes.
- Add rollback and champion/challenger comparisons; keep promotion human
  controlled for consequential changes.
- Compare new open-weight models behind the same interface using matched tasks,
  measured latency, resource use, and verified exact-version licenses.
- Investigate techniques inspired by published RSI research, including
  Darwin Gödel Machine and AIDE², without assuming their claims transfer.

**Exit gate:** Evidence of repeatable improvement in at least one bounded
domain, with regression and contamination checks. If absent, report failure
and revise hypotheses rather than weakening tests.

## Days 61–90: independent validation and private prototype

- Replicate promising gains with fresh, previously unseen evaluation items
  and documented seeds/configurations.
- Test whether improved proposal/evaluation strategies improve later cycles;
  distinguish ordinary optimization from genuine recursive gains.
- Red-team prompt injection, unsafe patch proposals, dependency supply-chain
  attacks, resource exhaustion, unauthorized network calls, and data leakage.
- Build a minimal private owner interface to inspect experiments, approve
  changes, and roll back. The animated companion remains a separate module.
- Prepare a private research pilot and explicit stop conditions. Commercial
  launch is not part of this 90-day acceptance gate.

**Exit gate:** Demonstrate or clearly falsify bounded RSI claims with
inspectable evidence. Open-ended RSI is not a required or promised outcome.

## Non-negotiable controls

- Never merge into main, deploy publicly, incur charges, access secrets, or
  modify frozen baselines without explicit owner approval.
- Never silently activate an external model or download unreviewed weights.
- No automatic deployment or model promotion. Candidate experiments remain
  isolated and reversible.
- Keep model weights, keys, user conversations, and training data out of Git.
- Preserve experimental provenance, negative results, and benchmark integrity.
- Check exact model version, commercial license, and security before use.
- Favor local/free inference; don't circumvent service limits or policies.

## Scorecard for every RSI milestone

Report: candidate count; accepted/rejected count; deterministic pass rate;
held-out accuracy delta and uncertainty; regressions; contamination status;
runtime/compute; model provenance; rollback availability; and whether any
future-cycle improvement was actually observed. Mark unmeasured metrics
explicitly as **not measured**.

## Current verified state and blockers

- APL-001 research branch has sandbox/policy infrastructure, local inference
  adapters, model router, and offline benchmark runner; CI passed through
  commit 472fb237 on 2026-10-24.
- Local Ollama adapter remains dormant; the public Safari demo is scripted.
- No real local model benchmark, independently verified RSI improvement,
  or sustained recursive gain has yet been demonstrated.
- Owner has not yet installed Ollama and Git on the HP.
- Exact local model/version/license and private integration remain undecided.
- Hardware performance and commercial readiness remain unverified.
